# Architecture decision records

Read `docs/DECISIONS.md` to find relevant decisions. Create an ADR only for a
significant durable choice, not each implementation detail or task update.
Number new files sequentially. Use context, decision, why, alternatives,
consequences, evidence/human approval and supersession. Mark proposed choices
PROPOSAL until authorized; do not invent retrospective human approval.

Accepted records describe existing approved policy/contracts. Leave historical
records intact; a new decision names `Supersedes: <path>` and the old record names
its replacement. Active task progress belongs in `docs/features/`, not here.
